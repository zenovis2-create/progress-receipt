# Improvements to progress-receipt v0.1.0

A skeptical review of the v0.1.0 tree, working from correctness outward. Every entry below was reproduced first and fixed second; the suite is green on Windows with Python 3.11, 3.12, and 3.13 (55 tests, up from 29). Python 3.10 is declared supported but is not installed on this machine — that gap is now recorded as a `blocked` claim in the self-report and added to the CI matrix rather than assumed.

## What I would still do before Show HN

1. **Push and watch CI go green.** Nothing here has run on a hosted runner. The matrix now includes 3.10, which is the one configuration I could not exercise at all — I would expect a real failure there before anything else, since it has genuinely never been run.
2. **Install Python 3.10 locally and regenerate the self-report.** The blocked claim is honest, but "our own receipt says our minimum supported version is untested" is a weak look on the front page. Better to make it verified.
3. **Decide what `report.status` means when claims disagree.** The contract lets a `verified` report contain a `blocked` claim, which is what the self-report now does. That is defensible, but it is the first thing a skeptical reader will poke at, and the contract should state the rule explicitly rather than leave it to inference.
4. **Add a fuzz/property test for the sanitizer.** The regex set is now large enough that the next contributor will break something subtly. Generating random text with injected secrets and asserting neither leakage nor mangling would be cheap and would catch the class of bug this review found by hand.
5. **Reconsider the `tokens = load()` redaction.** Security-first is the right default, but it will mangle real commit subjects and file paths in a way users will notice and file issues about. A `--no-redact-assignments` escape hatch, or value-shape heuristics, would be worth designing before the first wave of users hits it.
6. **Bound the worktree fingerprint's cost.** It hashes every untracked file's content. In a repo with large untracked artifacts that are not gitignored, collection will be slow for reasons the user cannot see. At minimum, warn above a threshold.
7. **Record the demo GIF.** The written summary helps, but the demo's whole value is that you see the report. That is the single highest-leverage remaining launch asset.
8. **Get one outside reader to try `uvx --from . progress-receipt demo` cold.** Every claim in the README is now something I checked, but I am not a first-time reader, and the trust argument only lands if a stranger reaches the report without confusion.
